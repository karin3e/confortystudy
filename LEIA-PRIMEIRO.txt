COMFORTSTUDY — PACOTE PARA PUBLICAÇÃO NO GITHUB PAGES
=====================================================

Este pacote preserva o painel e prepara autenticação e sincronização com Firebase.
IMPORTANTE: nenhum arquivo pode conter as credenciais do SEU projeto Firebase antes de você criá-lo. Por isso, o site não será funcional com contas reais até concluir a configuração abaixo. Isso é uma dependência externa, não algo que eu possa preencher sem acesso ao seu console.

PASSO A PASSO — FAÇA NESTA ORDEM
--------------------------------
1. Crie o projeto em https://console.firebase.google.com/
   Nome sugerido: ComfortStudy.
2. No projeto, adicione um aplicativo Web (ícone </>), registre-o e copie a configuração.
3. Abra firebase-config.js no VS Code. Substitua cada valor COLOQUE_... pelos valores exatos da configuração Web do Firebase. Não publique credenciais de conta de serviço nem chaves privadas.
4. No Firebase Console, abra Authentication > Sign-in method e ative E-mail/senha.
5. Em Authentication > Settings > Authorized domains, adicione o domínio do GitHub Pages, por exemplo SEU-USUARIO.github.io (sem https:// e sem caminho).
6. Abra Firestore Database e crie o banco. Em Rules, publique o conteúdo de firestore.rules. Não use regras públicas.
7. Copie TODOS os arquivos desta pasta para a raiz do repositório do GitHub Pages. A pasta icons precisa ser enviada também.
8. No GitHub, em Settings > Pages, escolha a branch e a pasta raiz (ou a pasta que você realmente usa para publicação).
9. Espere o deploy terminar e abra o site usando HTTPS.
10. Teste: cadastro, sair, login, recuperação de senha, criar tarefa/prova/conteúdo, abrir a mesma conta em outro navegador e verificar sincronização. Crie uma segunda conta para verificar que ela não vê os dados da primeira.

ARQUIVOS IMPORTANTES
--------------------
- index.html: entrada/login.
- cadastro.html: cadastro.
- recuperar-senha.html: recuperação por e-mail.
- index_2.html: painel principal.
- script.js e style_dashboard.css: funções e aparência do painel.
- firebase-config.js: configuração pública do aplicativo Firebase (valores do seu projeto).
- firebase-init.js, auth.js, cloud-sync.js: autenticação e sincronização.
- firestore.rules: regras de acesso por usuário.
- service-worker.js, manifest.json, icons/: instalação como PWA.

O QUE NÃO É POSSÍVEL ENTREGAR ATIVADO SEM CONFIGURAÇÃO EXTERNA
-------------------------------------------------------------
- Firebase Auth/Firestore não funcionam até você criar o projeto e inserir a configuração.
- Notificações push quando o site está completamente fechado exigem configuração adicional de Web Push e um serviço de envio no servidor.
- Pagamentos reais do Premium exigem provedor de pagamento e validação no servidor; o botão/plano visual não equivale a cobrança real.
- Antes de divulgar publicamente, publique política de privacidade/termos e teste em iPhone, Android e computador.
- GitHub Pages é hospedagem estática: não guarda segredos de servidor e não executa funções backend próprias.

SEGURANÇA
---------
- As regras Firestore restringem leitura e escrita ao UID autenticado.
- A configuração Web do Firebase é pública por desenho; a proteção depende das regras e das configurações do Firebase.
- Nunca coloque senhas de usuários, service-account JSON ou credenciais privadas no repositório.
- Faça backup dos dados locais antigos antes de trocar a versão. Senhas de um login local antigo não são migradas; os usuários devem criar conta no Firebase.

VALIDAÇÃO DO PACOTE
-------------------
Os arquivos JavaScript foram verificados sintaticamente nesta preparação. Isso não substitui testes de ponta a ponta com um projeto Firebase real e dois usuários reais.
