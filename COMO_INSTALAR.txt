COMFORTSTUDY — PACOTE FIREBASE + GITHUB PAGES

IMPORTANTE: o pacote de código está preparado, mas não pode autenticar contas reais até você criar/configurar seu projeto Firebase. Não publique como pronto para o público antes dos testes do arquivo CONFIGURAR_FIREBASE.md.

ARQUIVOS
- index.html: login com Firebase Authentication
- cadastro.html: criação de conta real
- recuperar-senha.html: envio de link de redefinição por e-mail
- index_2.html + script.js + extras.js + style_dashboard.css + extras.css: painel e funções de estudo
- firebase-config-v2.js / firebase-init.js / auth.js / cloud-sync.js: integração Firebase
- firestore.rules: regras de acesso por usuário
- storage.rules: regras de acesso aos anexos no Firebase Storage
- manifest.json / service-worker.js / icons/: instalação PWA

PASSOS
1. Crie um projeto em https://console.firebase.google.com/.
2. Ative Authentication > E-mail/senha. Ative Google se quiser login Google.
3. Crie um banco Cloud Firestore.
4. Copie a configuração do aplicativo Web para firebase-config-v2.js, substituindo todos os valores COLOQUE_... .
5. Publique as regras de firestore.rules em Firestore Database > Rules.
6. Ative Firebase Storage no mesmo projeto, confirme o campo storageBucket em firebase-config-v2.js e publique storage.rules em Storage > Rules.
7. No Authentication > Settings > Authorized domains, adicione SEU-USUARIO.github.io (sem https e sem caminho).
8. Envie todos os arquivos, inclusive extras.js, extras.css, storage.rules e a pasta icons para o repositório GitHub Pages.
9. Abra o endereço HTTPS e teste criação de conta, login, recuperação de senha, anexos em dois dispositivos, dados sincronizados e isolamento entre duas contas.

SEGURANÇA E LIMITAÇÕES
- Não há senha administrativa nem service-account neste pacote. Nunca coloque credenciais administrativas no GitHub.
- As senhas são geridas pelo Firebase Authentication; o projeto não salva senhas no localStorage.
- Dados antigos do protótipo só são importados quando o e-mail local anterior coincide com o e-mail autenticado. Faça backup antes de atualizar.
- Notificações com o app totalmente fechado exigem Web Push e um serviço de envio no servidor; ainda não estão incluídas.
- Os cadastros ficam abertos, e cada conta sincroniza os próprios dados. Com o Firebase Storage ativado e as regras publicadas, fotos e PDFs de tarefas, matérias e leitor de PDF podem ser abertos em outros aparelhos. Sem essa configuração, anexos pequenos continuam disponíveis localmente e no backup.
- Os avisos internos são marcados como lidos ao tocar neles e podem ser consultados no histórico. Avisos nativos dependem da permissão do navegador; entrega com o app fechado precisa de Web Push e servidor.
